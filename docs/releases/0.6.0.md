# Brown Octopus 0.6.0

Brown Octopus 0.6.0 is the measurement and operational-hardening release.
It keeps the validated production retrieval strategy and adds the diagnostics
needed to improve it safely.

## Highlights

- Added completed indexing reports for `create`, `update`, `add`, and source
  removal, including discovery, embedding, total duration, and embedded-count
  metrics.
- Added incremental embedding behavior so unchanged capabilities are not
  re-embedded during incremental operations.
- Added optional per-index background indexing jobs with one active job per
  index, configurable queue capacity, coalescing, rejection, and wait policies.
- Added retrieval timing and context-size diagnostics to `retrieve_result()`.
- Added synthetic retrieval scaling benchmarks across capability-universe
  sizes and query-length profiles.
- Added a real-runtime retrieval benchmark for local and PostgreSQL-backed
  indexes.
- Added a reviewed retrieval-evaluation harness and experimental score-gap
  clustering policy. The production Min-4 + Bounded Max Gap selector remains
  unchanged.
- Replaced stale managed spaCy plugin directories during model setup, avoiding
  incompatible leftover plugin packages after upgrades.

## Compatibility

- Existing direct APIs remain available: `await index.create()`,
  `await index.update()`, and `await index.add(...)`.
- `create()` reuses an existing snapshot unless `replace=True` is supplied.
- `add()` remains incremental and preserves existing capabilities.
- Retrieval defaults, TTL behavior, active-cap behavior, source filtering,
  and result contracts remain unchanged.
- Background jobs are optional and process-local.

## Validation

- Non-external test suite: **245 passed, 7 deselected**.
- Documentation Python and JSON examples parse successfully.
- Synthetic indexing and retrieval benchmark commands completed locally.
- Policy evaluation reports incomplete historical ranking coverage explicitly;
  missing rankings are not counted as successful retrievals.

The real-provider benchmark is included for deployment environments with the
required models already prepared. This release does not claim a new retrieval
quality baseline until the complete Recall@K, Precision@K, and nDCG@K harness
has been run against the current production selector.
