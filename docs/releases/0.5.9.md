# Brown Octopus 0.5.9

## Background indexing jobs

Large discovery and embedding operations can now run through an optional
per-index background queue:

- `submit_add()` queues incremental source additions.
- `submit_update()` queues configured-source synchronization.
- `submit_create()` queues initial creation or explicit replacement.
- `IndexJob` exposes status, result, error, timestamps, and JSON-safe
  snapshots.
- One job runs at a time for each index.
- Pending additions are coalesced by default.
- `reject` and `wait` queue policies are available.
- Retrieval continues to use the last successfully published snapshot while an
  indexing job runs.
- `close()` cancels jobs that have not started and lets the active operation
  finish safely.

The existing `await index.create()`, `await index.update()`, and
`await index.add(...)` APIs remain unchanged.

The queue is process-local. Multi-worker deployments must route one index to a
single owner or provide distributed job coordination in the host application.
