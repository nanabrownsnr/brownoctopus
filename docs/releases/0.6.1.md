# Brown Octopus 0.6.1

Configurable per-intent selection and independent response limits.

`OctopusConfig(min_tools=4, max_tools=32, min_gap_percent=2.0,
active_cap=60, max_returned_tools=20)` allows adaptive selection of up to 32
tools per intent, retains up to 60 tools in each session, and returns at most
20 tools per request. Configure the index with `OctopusIndex(config=config)`.
The defaults remain 4/16/2.0; the response limit defaults to `None`.

Environment equivalents are `OCTOPUS_MIN_TOOLS`, `OCTOPUS_MAX_TOOLS`,
`OCTOPUS_MIN_GAP_PERCENT`, `OCTOPUS_ACTIVE_CAP`, and
`OCTOPUS_MAX_RETURNED_TOOLS`. Omit the last variable for unlimited responses
within the retained session context.

Each intent receives its own adaptive selection before merging and
deduplication. A capped response allocates tools round-robin across intents,
then fills remaining slots with recently refreshed retained tools. Omitted
tools stay in session state until TTL expiry or active-cap eviction. A cap
smaller than the number of intents cannot cover every intent; diagnostics
report response truncation. Diagnostics remain enabled by default.

Empty PostgreSQL and MongoDB snapshots now load null embeddings as `None`,
allowing the first incremental addition. Populated snapshots with absent
embedding matrices continue to raise an error.

The release also includes retrieval benchmark tooling and candidate coverage
diagnostics from the three commits following 0.6.0.

Validation: 256 offline tests and four live PostgreSQL/pgvector and MongoDB
tests passed. Database checks cover empty creation, first addition, unchanged
re-addition, reopening, and retaining existing capabilities during additions.
