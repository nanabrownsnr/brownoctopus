# Brown Octopus 0.5.8

## Index lifecycle and source management

- `OctopusIndex.remove_source()` now removes capabilities incrementally by
  source ID or MCP URL.
- Source removal works after reopening an existing index without source
  objects (`sources=[]`).
- The per-capability removal API was removed in favor of source-level removal
  and authoritative source synchronization.
- Empty indexes and existing snapshots have clearer lifecycle behavior.
- Capability update reports now identify the operation and expose structured
  completion, change counts, and serialization details.

## Indexing performance and resource controls

- `update()` reuses unchanged embedding rows when the provider is compatible,
  avoiding a full re-embedding pass for unchanged capabilities.
- Local embedding uses a bounded default batch size of 8 and a 512-token input
  limit.
- Local embedding device selection is configurable with
  `OCTOPUS_EMBEDDING_DEVICE`.
- Batch size, maximum sequence length, and CUDA-to-CPU OOM fallback are
  configurable with environment variables.
- CUDA out-of-memory during local embedding retries on CPU with batch size 1
  when fallback is enabled.

## Documentation and validation

- Production documentation now covers source lifecycle, embedding resource
  controls, and the Phase 1/Phase 2 roadmap.
- Added regression coverage for incremental updates, source removal, empty
  indexes, device controls, and OOM fallback behavior.

## Compatibility

Existing `await index.create()`, `await index.update()`, and
`await index.add(...)` workflows remain supported. Background indexing queues
are intentionally not part of 0.5.8 and are planned separately.

## Validation

- Full non-external suite: **232 passed, 7 deselected**.
