Brown Octopus V3 Freeze Handoff
===============================

Status
------
Brown Octopus V3 is frozen. No ToolQP, DTDR, agent evaluation, retrieval
heuristics, parameter tuning, or benchmark-label changes were made.

Git commit
----------
72b200937486ca7413e1bfbd0e2abc6c3787a3aa
Commit message: Freeze Brown Octopus V3 selector

Final V3 architecture
---------------------
User query
  -> spaCy en_core_web_trf operational intent decomposition
  -> Qwen/Qwen3-Embedding-0.6B per-intent dense ranking
  -> select_min4_bounded_max_gap per intent
  -> merge and deduplicate
  -> active capability memory
  -> TTL 8 turns and global active cap 30
  -> final capability context

Frozen selector configuration:
MIN_TOOLS=4
MAX_TOOLS=16
MIN_GAP_PERCENT=2.0

The minimum-four floor is applied before merge/deduplication for each
operational intent. Fewer than four available ranked tools are returned as-is.

Selector implementation
-----------------------
Production selector:
src/octopus/selection.py :: select_min4_bounded_max_gap

It calls the existing select_bounded_max_gap implementation, then returns:

min(max_tools, max(min_tools, bounded_max_gap_selected_count))

No second Max Gap implementation, score threshold, confidence rule, or
failure-specific heuristic was added.

Production integration:
src/octopus/retriever.py

The generic evaluator adapter is named brown_octopus_v3 and returns the
standard RetrievalResult interface with method/configuration metadata.
